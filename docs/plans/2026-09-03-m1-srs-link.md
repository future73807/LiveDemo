# M1: SRS 流媒体链路实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Docker 启动 SRS 5，跑通「ffmpeg RTMP 推流 → HTTP-FLV/HLS/WebRTC 拉流」完整链路验证。

**Architecture:** SRS 单容器部署，挂载本地 `srs/srs.conf`；本阶段不含业务后端，`http_hook` 回调留到 M2 接入 live-service 时再开启，避免回调不可达导致推流被拒。docker-compose.yml 本阶段只含 srs 服务，后续里程碑逐步追加。

**Tech Stack:** Docker Compose、`ossrs/srs:5`、ffmpeg（拉流端合成测试源）、ffprobe（验证）。

**验收标准（对应设计 §9 M1）:**
- `GET http://localhost:1985/api/v1/versions` 返回 major=5
- ffmpeg 推流后 `GET /api/v1/streams/` 出现 `live/test`
- `ffprobe http://localhost:8080/live/test.flv` 输出 `h264,aac`
- 浏览器打开 SRS 自带播放器页可看到 WebRTC 画面

### Task 1: SRS 配置文件

**Files:**
- Create: `srs/srs.conf`

- [x] **Step 1: 写入 srs.conf**

注意：本阶段**不配置** `http_hook`（live-service 尚不存在，回调不可达会导致 on_publish 校验失败、推流被拒）；M2 Task 8 再追加。

```conf
listen              1935;
max_connections     1000;
daemon              off;
srs_log_tank        console;

http_server {
    enabled         on;
    listen          8080;
}

http_api {
    enabled         on;
    listen          1985;
}

rtc_server {
    enabled         on;
    listen          8000;
    # Docker 部署必须指定候选地址，compose 中通过环境变量注入
    candidate       $CANDIDATE;
}

vhost __defaultVhost__ {
    # RTMP 推流自动转 WebRTC 可播（设计 §4.2）
    rtc {
        enabled     on;
        rtmp_to_rtc on;
    }
    hls {
        enabled         on;
        hls_fragment    2;
        hls_window      6;
    }
}
```


### Task 2: docker-compose（仅 srs）

**Files:**
- Create: `docker-compose.yml`

- [x] **Step 1: 写入 compose 文件**

```yaml
services:
  srs:
    image: ossrs/srs:5
    container_name: livedemo-srs
    restart: unless-stopped
    ports:
      - "1935:1935"       # RTMP 推流
      - "1985:1985"       # HTTP API + WebRTC 信令(WHEP)
      - "8080:8080"       # HTTP-FLV / HLS
      - "8000:8000/udp"   # WebRTC 媒体
    environment:
      - CANDIDATE=127.0.0.1   # 本机演示用；公网部署改为服务器公网 IP
    volumes:
      - ./srs/srs.conf:/usr/local/srs/conf/srs.conf
```

- [x] **Step 1: 后台推一路合成测试流**

无需本地视频文件，用 ffmpeg lavfi 合成画面与音频：

```bash
ffmpeg -re -f lavfi -i "testsrc2=size=1280x720:rate=30" -f lavfi -i "sine=frequency=1000" -c:v libx264 -preset veryfast -tune zerolatency -pix_fmt yuv420p -c:a aac -b:a 128k -f flv rtmp://localhost:1935/live/test
```

保持该命令运行（终端 A）。

- [x] **Step 2: 验证流已注册**

```bash
curl -s http://localhost:1985/api/v1/streams/
```

预期：`streams` 数组包含 `{"name":"test","app":"live",...}`，且 `"publish":{"active":true}`。

- [x] **Step 3: Commit 验证脚本（可选沉淀）**

创建 `scripts/push-test.sh` 便于复用：

```bash
#!/usr/bin/env bash
# 推一路合成测试流到 SRS，用法: ./push-test.sh [streamKey] [rtmpHost]
set -e
KEY="${1:-test}"
HOST="${2:-localhost}"
exec ffmpeg -re -f lavfi -i "testsrc2=size=1280x720:rate=30" \
  -f lavfi -i "sine=frequency=1000" \
  -c:v libx264 -preset veryfast -tune zerolatency -pix_fmt yuv420p \
  -c:a aac -b:a 128k -f flv "rtmp://${HOST}:1935/live/${KEY}"
```


## 验证记录

**日期：** 2026-09-03（Asia/Shanghai）
**执行环境：** Windows + Docker 29.6.2（本机无 ffmpeg/ffprobe，全部经 Docker 容器执行；git 2.52.0）
**SRS 版本：** 5.0.213（镜像 `ossrs/srs:5`）

| 验收项 | 结果 | 实际输出摘要 |
| --- | --- | --- |
| versions API（major=5） | ✅ | `{"code":0,...,"major":5,"minor":0,"revision":213,"version":"5.0.213"}` |
| streams 注册（live/test，publish.active=true） | ✅ | `name:"test", app:"live", publish.active:true, video:H264 High 1280x720, audio:AAC 44100Hz LC` |
| HTTP-FLV（ffprobe `http://srs:8080/live/test.flv`） | ✅ | `aac`、`h264`（输出顺序 aac 在前，属 ffprobe 枚举顺序差异，编码齐全） |
| HLS（ffprobe `http://srs:8080/live/test.m3u8`） | ✅ | `aac`、`h264`（两组输出，对应 HLS 音视频轨道枚举） |

| WHEP 信令端点（`POST /rtc/v1/whep/?app=live&stream=test`） | ✅ 超预期 | 合法 SDP offer（BUNDLE/rtcp-mux/recvonly）→ **HTTP 201 + 完整 SDP answer**（`o=SRS/5.0.213(Bee)`、`s=SRSPlaySession`、`msid-semantic: WMS live/test`、含 ICE 凭据与 DTLS 指纹）；畸形 SDP 触发服务端 `5012 RtcSdpDecode` / `5018 RtcSdpNegotiate` 错误日志，证明路由正确非 404 |

1. 本机无 ffmpeg/ffprobe：Task 4 推流与 Task 5 探测均改用 Docker 容器（`jrottenberg/ffmpeg:6-alpine`，加入 `livedemo_default` 网络直连 `srs` 服务名），后台容器 `push-test` 对应计划"终端 A 保持运行"。
2. SRS 5.0.213 启动横幅为 `XCORE-SRS/5.0.213(Bee)`，未出现计划预期的 `srs works!` 字样（版本差异），日志无 ERROR，服务正常。
3. SRS 5.0.213 对 WHEP 畸形 SDP 直接断连（curl 退出码 52、`http_code=000`）而非回写 4xx/5xx；改用合法 SDP offer 验证获 201 + answer，信令链路完整可用，验收结论不变。
4. 仓库已初始化（历史提交 d8cd32e、edab06c），`git init` 跳过；`资源.txt` 不存在，Task 0 首次提交实际仅新增 `.gitignore`（README.md/docs 已在历史提交中）。
